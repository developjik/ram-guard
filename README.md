# RAM Guard

스왑데스(swap-death) 방어 맥 메뉴바 앱. 가용 메모리가 임계 이하로 떨어지면
같은 사용자의 가장 큰 RSS 프로세스를 SIGKILL로 즉시 종료해 시스템 전체
멈춤(수 시간 스왑 헬)을 막습니다. 검증된 `oom-watchdog.sh`의 Swift/AppKit 이식.

## 원리

- 가용 메모리 = `vm_stat`의 free + speculative 페이지 합계(`host_statistics64`)
- 10초 폴(전용 직렬 큐 + `DispatchSourceTimer`, 첫 틱 즉시 발화)
- 임계 이하 → 최대 RSS 후보 1개에 `kill(pid, SIGKILL)` 즉시 직행
- 보조 트리거: 가상메모리 헤드룸(현재 스왑 여유 + 디스크 여유) < VM 여유
  임계(기본 8GB, 임계치 탭에서 4~32GB 조절) && 가용 ≤ 임계×2 → 조기 발동.
  macOS 스왑 파일은 스토리지 여유만큼 동적으로 자라므로 진짜 한도는
  스토리지 — 헤드룸이 넉넉하면 절대 발동하지 않음 (스왑 사용률만 높다고
  킬하면 무고한 앱을 죽이는 일)
- 스래싱 가드(3차 트리거): 10초당 스왑 쓰기 128MB 이상이 3틱(~30초) 연속
  지속 → 가용 메모리가 임계 위여도 발동. AI 워크로드처럼 거대한 워킹셋이
  계속 스왑으로 밀려나는 동안 가용 수치는 임계 위를 유지하며 시스템이
  멈추는 케이스를 잡는다. 순간 버스트(모델 로드 등)는 지속 조건을 못 넘김.
  패널 스왑 타일 바가 주황(스필)→빨강(스래싱)으로 바뀌고 상태 문장에
  "스왑 I/O N/10초 ⚠️" 표기, 기록 사유에 "swap thrash"로 남김
- 표시 밴드 = 엔진 발동 조건 동기화: 2차(합산 여유 부족)·3차(스래싱)
  발동 시 패널·메뉴바가 🔴 메모리 위험으로 올라가고, 스왑+디스크 헤드룸이
  8GB 밑으로 얕아지면 가용이 넉넉해도 최소 🟡. 상태 문장에 "스왑 여유 X ⚠️"
  표기, 총 가용(RAM+VM) 타일도 주황색으로 전환. 방어 판단 자체는 엔진 조건
  그대로 (표시가 판단을 흔들지 않음)
- 킬 후 30초 쿨다운(연쇄 킬 방지), 후보 공집합 시 로그만
- 후보 조건(모두 만족): 같은 uid · 메모리(phys_footprint) > 1,000,000 KiB(≈976.6
  MiB) — RAM+압축 합계, Activity Monitor '메모리' 열과 동일 ·
  `/System` `/usr` `/bin` `/sbin` 경로 아님 · `kernel_task` 아님 · 자기 자신
  (pid/번들) 아님 · 제외 목록에 매칭 안 됨 · 경로 해석 가능
- 첫 실행은 **observe 전용**(킬 후보를 기록만). 패널에서 방어로 전환하면
  실제 킬을 시작하고 이 상태는 재시작/재부팅 후에도 유지됩니다.

## 요구 사항

- Apple Silicon 맥 (arm64). 인텔 맥 미지원.
- macOS 13 Ventura 이상.

## 설치

1. [Releases](../../releases)에서 `RamGuard-<버전>-arm64.zip` 다운로드
2. 압축 해제 → `RamGuard.app`을 `/Applications`로 이동
3. **무서명(ad-hoc)·비공증 빌드입니다.** 첫 실행 차단 시:
   - 시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기" (Sequoia 이상 현행 절차)
   - 우클릭 → 열기는 구버전 우회로로 레거시에서만 동작
   - 터미널 부록: `xattr -d com.apple.quarantine /Applications/RamGuard.app`
4. 실행하면 메뉴바에 방패 아이콘(무색 = observe)

## 첫 실행 가이드

처음 실행하면 사용법 안내 창이 뜹니다 (패널의 "사용법" 버튼으로 언제든 다시 볼 수 있어요).

1. 방패 아이콘(observe) 상태에서 평소처럼 작업
2. 메모리 압박 상황이 오면 패널·이력 창에 🟡 '종료 직전' 기록이 쌓임 —
   실제로 죽었을 프로세스를 미리 확인
3. 동작에 확신이 서면 패널 상단 캡슐에서 **"방어"로 전환** (초록 방패). 이후
   임계 이하에서 실제 킬 시작
4. 임시 중단은 "관찰" 전환 또는 앱 종료. 긴급 정지:
   `defaults write dev.ramguard.RamGuard ramguard.posture -string observe`

## 사용법

메뉴바의 방패 아이콘을 클릭하면 패널이 열립니다 (고정 높이, 3탭):

- 메뉴바: 방패 아이콘 + 총 사용량(RAM 사용 + 스왑 사용) 컴팩트 표기
  (평소 흰색 / 임박 노랑 / 위험·발동 빨강), 매 10초 갱신. 툴팁에 총 사용량 /
  한도 · RAM 가용 · 남음 정리
- 상단: 관찰 ↔ 방어 전환 캡슐 + 현재 모드 설명
- 상태 카드(합산 풀 기준): 링 게이지(합산 사용률 아크 + 가상메모리 여유 임계
  노치) + 큰 총 사용량 숫자(밴드 색, 옆에 한도 표기) + 한국어 상태 문장
  (🟢 여유 / 🟡 임박 / 🔴 위험) + 최근 10분 추이 스파크라인(임계선 점선) +
  사용(합산%)·스왑·총 가용(RAM 가용 + 스왑·디스크 여유)·한도 스탯 타일.
  한도 = 설치 RAM + 할당된 스왑 + 디스크 여유(새 스왑파일이 자랄 수 있는
  공간)이고, 한도 − 총 사용량 = 총 가용. 위험 밴드 판정은 엔진 조건
  (물리 가용 + 스왑 헤드룸 + 스래싱) 그대로
- 탭 — 보호 앱: 지금 메모리 큰 앱 (상위 6개, 앱 아이콘 + 메모리 + 스위치 =
  제외·보호, 즉시 적용) + 제외 파일 열기
- 탭 — 임계치: 슬라이더(0.5GB~RAM의 25%, 최소 4GB 상한, 64MB 스텝) +
  가용 프리셋 칩(0.5G/1.2G/2G/4G) + 가상메모리 여유 임계 칩(4/8/16/32G,
  기본 8G — 스왑+디스크 헤드룸이 이 밑으로 내려가면 🟡, 가용도 낮으면
  조기 발동). 임계가 현재 가용보다 크면 "⚠️ 방어 곧 발동" 경고(하드 제한
  없음). 변경은 다음 틱(최대 10초)에 즉시 반영되고 재시작 후 유지
- 탭 — 기록: 최근 방어 기록 3건(종류별 도트 색) + 전체 이력 보기 (창:
  타임라인 레일 + 도트, 종류별 색, 시간 우측 정렬)
- 하단: 로그인 시 자동 시작 토글 · 사용법 · 종료

아이콘: 방패(무색) = observe / 초록 방패 = armed / 빨강 방패 = 발동 직후

## 제외 목록

`~/.config/ramguard/exclusions.txt` — 한 줄에 프로세스 이름 하나.
`#`로 시작하는 줄은 주석. **대소문자 무시 부분 매칭**(예: `cursor`는
"Cursor Helper (GPU)"도 보호) — 프로세스 이름(16자로 절단됨)과 실행 파일
이름 양쪽에 대조하므로 긴 패턴도 보호됩니다. 파일이 없으면 처음 실행 시 템플릿이 자동
생성됩니다. 패널의 "보호 앱" 탭에서 스위치로 추가·해제하면 **즉시(다음 틱)
적용**되고 파일에도 저장됩니다. 파일을 직접 수정한 경우에만 앱 재시작이 필요합니다.

예:

```
# 에디터·세션 인프라 보호
Cursor
bun
node
ghostty
```

## v1 한계 (명시적)

1. **1GB 미만 다수 프로세스 합산 압박은 방어 못 함** — RSS 하한 1,000,000 KiB
   미만 프로세스는 후보가 아니므로, 여러 개가 쌓여 스왑데스를 유발하는
   상황은 잡지 못합니다 (v2 후보: 합산 기준).
2. **앱 크래시 중 무방어 공백** — 자동 재시작(KeepAlive)은 의도적으로
   넣지 않았습니다. 메뉴바 아이콘이 사라지면 앱이 죽은 것입니다.
3. **SIGKILL 즉시 종료로 미저장 데이터 손실 가능** — 희생 프로세스의
   저장 안 된 작업은 사라집니다. observe에서 먼저 확인하고 armed로
   전환하세요.
4. **인텔 맥 미지원.**

측정 기준: `phys_footprint` — resident + 압축 페이지 합계로, 커널이 메모리를
압축해도 줄어들지 않습니다. 초기 버전은 RSS(`resident_size`) 기반이라 커널
압축으로 큰 프로세스가 후보에서 빠지는 문제가 있었으나(원문 스크립트와 동일한
한계) footprint 전환으로 해소됐습니다.

## 소스에서 빌드

```sh
swift build                      # 디버그
./scripts/make-app.sh            # Release → dist/RamGuard.app (ad-hoc 서명·검증)
./scripts/make-release.sh        # zip까지 (배포용)
.build/debug/RamGuard selftest   # 내장 단위 스위트 (129 checks)
.build/debug/RamGuard once       # vm_stat 패리티 측정 1회
.build/debug/RamGuard uitour     # UI 렌더 QA — 패널 3탭·웰컴·이력 PNG (artifacts/)
./scripts/test/verify-vmstat.sh  # 측정 교차검증 (±5%)
```

macOS Command Line Tools만으로 빌드됩니다(Xcode 불필요).
